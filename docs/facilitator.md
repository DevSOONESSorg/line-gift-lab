# 職員向けガイド

## 事前準備

- **初めて使う前・アプリを更新したあとは、[動作チェックリスト](checklist.md) を職員が一度通す**
- 参加者用PCに Docker Desktop を入れ、**事前に一度 `docker compose up` を完了させておく**（初回は Laravel 本体のダウンロードで3〜5分かかる）
- コースBをやる場合は `docker compose --profile tunnel pull` も済ませ、事業所のネットワークで `*.trycloudflare.com` が使えるか確認
- 障害ドリルの症状カード（下の表の「症状カード」列）を印刷しておく
- コースBは、参加者本人のLINE（方法A）か、メールアドレスで作るビジネスID（方法B）を使う。前日までに本人に確認

## タイムテーブル例（1日4時間）

| 日 | 内容 |
|---|---|
| 1日目 | 起動 → 第0章 → 第1〜2章（全店舗共通）→ 第3〜6章（オリジナルの構築：つなぐところまで） |
| 2日目 | 第7〜10章 → 障害ドリル → 通しチェック・提出 |
| 3日目〜 | 希望に合わせて：コースB（本物のLINE）／コースC（コードを読んで直す） |

- エンジニア経験のある人は、1日目の後半からコースCを並行してよい（コースAの章を進めながら、その章のコードを読む）
- コースAを飛ばして B・C から始めるのはおすすめしない（詰まったとき、裏側を想像できないため）

## 声かけのポイント

- 最初に「**お客さん・オーナー・運営スタッフ**」の3つの役割を確認する。教材では疑似スマホが2台（左：お客さん、右：オーナー）並んでいて、両方を1人で操作する。本物の運営スタッフがスマホを触るのは動作確認のときだけ
- 詰まったら、まず「**裏側ビューで NG の行はある？**」と聞く。答えを言わずに、見る場所を示す
- 「なぜ？」の節は、読むだけでなく **自分の言葉で説明してもらう**
- 1人2役（個人アカウント／会社の作業アカウント）で混乱しやすい。画面上部の「ログイン中」を声に出して確認させる
- 管理画面を開いたら右下の環境表示（DEV）を見る習慣を、最初からつける（本番で役立つ）

## 障害ドリルの仕込み方

参加者が第10章まで終えたら、そのPCで職員が実行します。裏側ビューには仕込んだ記録は残りません。

```bash
docker compose exec app php artisan lab:drill                 # 症状カードの一覧
docker compose exec app php artisan lab:drill 3               # 3番を仕込む
docker compose exec app php artisan lab:drill random
docker compose exec app php artisan lab:drill 3 --store=club-azure
```

## コースCの見方

- 課題は `git diff` で提出してもらう。動くかどうかより、「どのファイルを・なぜ変えたか」を説明できるかを見る
- C1-2（辞退）、C2-2（期限切れの通知）、C3-2（店舗画像）は、実物の改修でもありそうな規模。できたら実物との違いを話すとよい

## 片付け

- コースB を行った人は、**B9 片付け** を職員の前で行ってもらう
- PC を次の人に渡す前に `docker compose exec app php artisan migrate:fresh --seed`（データの作り直し）

## 構築ナビを直すときのルール（手順が増えても必ず守る）

構築ナビ（`app/Services/BuildGuide.php`）は、手順の数・中身・順番があとで変わってもかまいません。ただし、次の4つは必ず守ります。

1. **やることを1行ずつ、はっきり書く**：「開く → 押す／選ぶ → コピー → 貼り付け → 確認」を、ボタン名・欄の名前そのままで書く。貼り付ける値が決まっているときは、値とコピーボタンを出す（秘密の値＝シークレット・トークンは出さない）
2. **終わったかは、実際の設定を見て判定する**（参加者の「できました」ボタンにしない）
3. **手順は飛ばせない**：前の手順が終わるまで、後ろの手順はグレーアウトし、中身もリンクも出さない
4. **終わったら「完了」と出し、一覧にチェックを付けて、次の手順を開く**

課題のお店を増やすときは `app/Services/BuildScenario.php` の `SCENARIOS` に1つ足します。構築ナビで選ぶと、そのお店は毎回「スタート地点」に作り直されます。
