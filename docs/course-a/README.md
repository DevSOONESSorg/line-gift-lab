# コースA：手順書の「意味」がわかる

実際の仕事では「店舗オンボーディング手順書」に沿って、お店を登録し、オリジナルを希望するお店にはそのお店の公式LINEをつなぎます。手順書どおりに操作すれば作業はできます。でも、**なぜその順番なのか、その値は何なのか**がわかっていないと、うまくいかないときに原因を探せません。

## まず、サービスの流れをつかむ

| 人 | すること |
|---|---|
| お客さん | 運営の公式LINEの「店舗に贈る」（**共通掲載**）か、**お店の公式LINE・QR**（オリジナル）から、商品を選んで**お店にギフトを贈る**。カードは初回だけ登録（銀行振込も可）。お店から**お礼動画**が届く |
| お店のオーナー | 運営の公式LINEを友だち追加 → **出店登録**（店舗情報・代表者・振込先・掲載方法）→ **商品登録**。ギフトが届いたら「受け取る」→ お礼を送る |
| 運営スタッフ（私たち） | **管理画面**で承認・slug・手数料・代理店・注文の確認。オリジナルのお店には **公式LINEの構築**。スマホは動作確認だけ |

この教材の疑似スマホは2台です。**左がお客さん、右がオーナー** のスマホです。お客さんのスマホには、役割がまざらないように運営の公式LINE（おくりギフト）を入れていません（本物では、お客さんが共通掲載のお店を探すために入れていることもあります）。本物の仕事で運営スタッフがスマホを触るのは、構築したあとの**動作確認**のときだけです。

## 進め方

手順書と同じ10のステップを教材アプリの中でやりながら、1つずつ

1. **やる** … 手順書と同じ操作をする
2. **裏側を見る** … [裏側ビュー](http://localhost:3000/inside) で、スマホ・LINE社・自社サーバーの間で何が起きたかを見る
3. **なぜ？** … その操作の意味を知る
4. **壊してみる** … わざと間違えて、どんな症状が出るかを体験する（そして直す）

の順で進めます。最後に、職員がこっそり壊した設定を直す「障害ドリル」に挑戦します。

## はじめる前に

- 教材アプリを起動しておく（[README](../../README.md#3-動かし方docker)）
- 管理画面のログイン：`admin@example.com` ／ `Taiken-2026`
- ブラウザで2つのタブを開いておくと便利です
  - タブ1：作業する画面
  - タブ2：[裏側ビュー](http://localhost:3000/inside)（自動で更新されます）
- 自分のお店の名前と slug（スラッグ）を決めておく。このコースでは、第3〜8章で公式LINEの構築を体験するため、**「オリジナル」を希望するお店** として登録します
  - 例：店名「クラブ アズール」、slug `club-azure`
  - slug は **半角の英小文字・数字・ハイフン** だけ。自分の名前を入れると区別しやすい（例 `yamada-cafe`）

## 「ログイン中」の切り替えについて

疑似Manager と 疑似Dev Console の上部に「ログイン中：」の欄があります。本物では別々のブラウザやアカウントでログインし直すところを、この欄で切り替えます。

| アカウント | 役 | 本物の仕事では |
|---|---|---|
| あなたの個人アカウント（オーナー役） | 公式アカウントを作る人 | お店のオーナー（体験では自分の個人LINE） |
| 会社の作業アカウント（support役） | 受け取って設定する人 | 会社の共通アカウント |

## 提出するもの

コースAの最後に、次の3つを提出してください。

1. **第11章の通しチェック**の画面キャプチャ（全部できたところ）
2. **障害ドリルの報告**（カードごとに3行）
   - どんな症状だったか
   - どこを見て原因がわかったか（裏側ビューのどの行か）
   - どう直したか
3. **ひとこと感想**：手順書のどの作業の意味が、いちばん「わかった」と思えたか
