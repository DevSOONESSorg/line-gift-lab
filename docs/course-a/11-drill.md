# 第11章 障害ドリル ／ 困ったときの見る場所 ／ 通しチェック

## 障害ドリル

職員が、あなたのお店の設定を **どこか1か所だけ** こっそり壊します。あなたには「症状カード」だけが渡されます。原因を探して直してください。

### 進め方

1. 症状カードを読む（例：「トークで話しかけても、botが返事をしない」）
2. 疑似スマホで症状を再現する
3. [裏側ビュー](http://localhost:3000/inside) で **NG** の行を探す（絞り込み →「NGだけ」）。行を開いて中身を読む
4. 下の「困ったときの見る場所」の表を使って、どこを直すか決める
5. 直したら、もう一度疑似スマホで確かめる
6. 報告を書く（症状 ／ どこを見てわかったか ／ どう直したか）

> NG が出ないこともあります。そのときは「どこまで届いているか」を見ます。スマホの行はあるのに LINE社の行がない？ LINE社の行はあるのに自社サーバーの行がない？

## 困ったときの見る場所

| 症状 | 見るところ |
|---|---|
| メッセージを送ってもギフトの案内が返ってこない（ケースAのお店） | Webhook の 検証 が 200 か ／ 応答設定の「チャット」がオフ・「Webhook」がオンか ／ Webhook URL の slug ／ 署名NG（シークレット）が出ていないか ／ 管理画面の「ギフト誘導を自動返信する」がオンか |
| 返事が2通来る | まず手順5で控えたケースを見る。ケースA：応答設定の応答メッセージがオフか ／ ケースB：管理画面の「ギフト誘導を自動返信する」がオフか |
| お店のキーワード応答（「お店の情報」など）が返らなくなった | 応答設定の応答メッセージがオンか ／ 応答メッセージの一覧の「利用」がオンか（ケースBのお店で応答メッセージをオフにすると、こうなる） |
| 「トークンが無効です」（401）・テスト送信の失敗 | アクセストークンを再発行したか → 管理画面の値を更新 |
| 「贈る」でちがうお店が開く | LIFF のエンドポイントURL の slug |
| 「準備中」と出る | 管理画面の「承認済み」 |
| 贈る画面に商品がない | 商品が「販売中」か（店舗詳細のメニュー一覧・オーナーの商品登録） |
| 「システムエラー LIFF app '…' was not found.」 | リッチメニューやQR（管理画面の LIFF ID）の打ち間違い。I と l、O と 0 を見まちがえていないか。コピーで貼り直す |
| 「400 Bad Request」で LIFF が開かない | LINEログインチャネルが「公開済み」か（「開発中」だと、お客さんは開けない） |
| お知らせが届かない | 注文が来た道の公式アカウントと友だちか（ブロックしていないか） |
| 「店舗に贈る」の一覧に出てこない | 「承認済み」と「共通アプリの店舗一覧に掲載する」の両方がオンか |
| 注文が「リクエスト中」のまま | オーナーの「受け取る」が必要。期限を過ぎると「期限切れ」 |
| 注文が「入金待ち」のまま | 運営の入金確認が必要。期限を過ぎると「キャンセル」 |

## 通しチェック（これが全部できれば完了）

上から順に消し込めば、抜けなく完了を確認できます。詰まったら各章に戻ってください。

**お店を用意する（第1〜2章）**
- [ ] 管理画面にログインし、右下の環境表示（DEV）を確認した
- [ ] オーナー役で、左下QR → 出店登録（店舗情報・代表者・振込先・掲載方法）をした
- [ ] オーナー役で、商品をテンプレートと自由入力で登録した
- [ ] 運営として、振込先を確認して「承認済み」にし、slug を決めた
- [ ] デフォルト手数料率と、月別手数料率を設定した

**オリジナル：お店の公式LINEに入れてもらう（第3章・第7章）**
- [ ] オーナー役で、権限管理で「運用担当者」を選び URL を発行 → 会社の作業アカウントに渡した
- [ ] 会社の作業アカウントで URL を開いて参加した（作業者を切り替えた）
- [ ] **何も変える前に**、応答メッセージ・キーワード応答の件数・あいさつを控え、ケースA／Bを判定した（構築ナビ手順5が完了）
- [ ] 会社の作業アカウントで Messaging API を有効化（プロバイダー＝運営・プライバシーポリシー＝会社のURL）した

**つなぐ（第4〜6章）**
- [ ] LINEログインチャネルを本番と同じ値（所在国・20文字以内のチャネル名・説明・会社のメール・プライバシーポリシー・2要素認証オフ）で作り、「公開」にした
- [ ] LIFF を `{slug}-gift`・Full・openid と profile・友だち追加オプション On (normal) で追加した
- [ ] ログインチャネルに、お店の公式アカウントをリンクした
- [ ] 長期トークンを発行し、管理画面に5つの値を **コピーで** 入力 →「設定整合性」がすべてOK
- [ ] Webhook URL を貼って 検証＝200 → Webhookの利用 を ON

**仕上げ（第7〜9章）**
- [ ] 応答設定をケースに合わせた（ケースB：応答メッセージ・あいさつはオンのまま＋自動返信オフ ／ ケースA：応答メッセージ・あいさつオフ＋自動返信オン）
- [ ] ケースBのお店で応答メッセージをオフにすると、お店のキーワード応答が止まることを体験し、元に戻した
- [ ] リッチメニューの「贈る」ボタンだけに LIFF URL を入れた（ほかのボタンはそのまま）
- [ ] 紐付け代理店を依頼書どおりにした（紹介コードまで確認）。代理店を作成し、店舗に紐付けた（店舗数が増えた）

**動作確認して完了（第10章）**
- [ ] お店の公式LINEから、カードを登録して贈った →「リクエスト中」
- [ ] 共通掲載から、銀行振込で贈った →「入金待ち」→ 管理画面で入金確認 →「リクエスト中」
- [ ] オーナー役で「受け取る」→「受取済み」→ お礼を送る →「お礼済み」
- [ ] お礼一覧でお礼を見た。送信履歴から領収書を出した
- [ ] lab:time-travel で期限切れを体験した
- [ ] 注文詳細の「状態の移り変わり」と売上集計を確認した
- [ ] 引き渡し前の最終確認：お店のいつもの動き（キーワード応答・ほかのボタン）が変わっていない（構築ナビ手順17が完了）

**理解のチェック（コースAならでは）**
- [ ] 5つの値のそれぞれの役割を、自分の言葉で説明できる
- [ ] Webhook の 検証 が 401 と 404 のとき、それぞれ何を疑うか言える
- [ ] 注文の状態の図を見ずに、カードの注文の一生を説明できる
- [ ] ケースAとケースBで、応答設定をどう変えるか・なぜかを説明できる
- [ ] 障害ドリルを1つ以上、裏側ビューを使って直せた
