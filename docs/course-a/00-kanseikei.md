# 第0章 完成形を触ってみる

> この章でわかること：お客さんがギフトを贈る入口（オリジナル・共通掲載）と、ギフトの一生（贈る → 受け取る → お礼）

教材アプリには、最初から見本のお店が入っています。

| お店 | 掲載方法 | お客さんの入口 |
|---|---|---|
| 見本バー | 共通掲載 | 運営の公式LINE「おくりギフト(dev)」→「店舗に贈る」 |
| シャンパンバー ルミエール（見本のお店） | オリジナル | シャンパンバー ルミエールの公式LINE → リッチメニュー「店舗ページ」 |

[疑似スマホ](http://localhost:3000/mock/phone) は2台並んでいます。**左がお客さんのスマホ、右がオーナーのスマホ** です（別々の人のLINE）。どちらのお店も、オーナーは右のスマホの人です。左で贈り、右で受け取ってみましょう。

## やること

### お客さんとして贈る（左のスマホ）

1. [疑似スマホ](http://localhost:3000/mock/phone) の **左（お客さん）** のトーク一覧から **シャンパンバー ルミエール** を開く
2. リッチメニューの **店舗ページ** → 商品（例：スタッフ乾杯用）の **この商品を送る** を押す
3. **送信者名**（最初はLINEの名前）・**贈る人**（空欄ならお店宛。例：スタッフの名前）・**メッセージ** を入れる
4. はじめてなので、支払いは **クレジットカード** で **カードを登録** する

   | 項目 | 入れる値 |
   |---|---|
   | カード番号 | `4242 4242 4242 4242` |
   | 有効期限 | `12/40`（今日より先ならなんでもOK） |
   | CVC | `123` |

5. 「ありがとうございました」の画面に **ORDER NO**（注文番号）が出る → **閉じる** → シャンパンバー ルミエールから「ご注文ありがとうございます」が届いている
6. もう一度 **店舗ページ** から贈ってみる。支払いに **登録済みカード VISA **** 4242** が出ていて、カード番号を入れずに **「VISA ****4242 で決済する」** で贈れる

### オーナーとして受け取って、お礼を送る（右のスマホ）

7. **右（オーナー）** のスマホで、おくりギフト(dev) のトークに「[シャンパンバー ルミエール] お客さん様から「○○」が贈られました」が届いている
8. お知らせの中のリンク（またはリッチメニューの **店舗管理**）→ **贈り物一覧** → **贈り物を受け取る** → **この贈り物を受け取る**（ここで決済が確定）
9. 左のスマホに、シャンパンバー ルミエールから「贈り物「○○」を受け取りました」が届く
10. 右のスマホで **お礼を送る**：メッセージを書いて送信（動画があれば添付。なくてもOK）
11. **左（お客さん）** のスマホに「お礼が届きました」が届く。リッチメニューの **お礼一覧** で見る

### もう1つの入口：共通掲載（読むだけ）

本物のサービスでは、お客さんが運営の公式LINE（おくりギフト）を友だち追加して、**「店舗に贈る」から共通掲載のお店（見本バーなど）を探して贈る** こともあります。

この教材では、左右のスマホの役割がまざらないように、**お客さんのスマホには運営の公式LINEを入れていません**。運営の公式LINEは、オーナー（右）が出店登録・店舗管理・お知らせの受け取りに使うもの、と覚えておきましょう。

> 試したいときは、左のスマホの検索に運営の公式LINEの @ID（管理画面の左下に出ています）を入れて友だち追加すると、「店舗に贈る」から見本バーに贈れます。試したら、トーク右上の ≡ から **ブロック** しておくと元の状態に近くなります。

> LIFF の開き方にも注目。お客さん向けの画面は **トークの上に下から出てきます（サイズ Tall）**。オーナーの店舗管理は **全画面（サイズ Full）** です。LIFF のサイズは Dev Console の LIFF タブで決めます（第4章）。

[裏側ビュー](http://localhost:3000/inside) を開いてみましょう（下から上へ、古い順）。

| だれ | 何をした |
|---|---|
| LINE社 | LIFF ○○ を開きます → エンドポイントURL …/liff/s/lumiere |
| 自社サーバー | カード **** 4242 を登録しました（次回からは入力不要） |
| 自社サーバー | 注文 #○ を作りました →「リクエスト中」… **カードは仮押さえだけ** |
| 自社サーバー | LINEにお願い POST /v2/bot/message/push … お客さんへは **シャンパンバー ルミエールのトークン**、オーナーへは **運営（共通チャネル）のトークン** で |
| 自社サーバー | 注文 #○: リクエスト中 → 受取済み（仮押さえしていたカードの決済を確定） |
| 自社サーバー | 注文 #○: 受取済み → お礼済み |

## 考えてみよう

- お客さん（左）へのお知らせはシャンパンバー ルミエールから、オーナー（右）へのお知らせは運営の公式LINEから届きました。なぜでしょう？
- 「受け取る」を押すまで、お金は動いていませんでした。なぜ買った瞬間に確定しないのでしょう？

答えは第10章でわかります。

## この章のゴール

- 第1〜2章：**すべてのお店**に共通する作業（出店登録・商品登録・承認・手数料）
- 第3〜8章：**オリジナルを希望したお店**のための、公式LINEの構築（運営スタッフの主な仕事）
- 第9〜10章：代理店の紐付けと、動作確認

シャンパンバー ルミエールと同じ状態を、**課題のお店「クラブ アズール」で作る**のがコースAです。クラブ アズールは、出店登録・公式LINE・リッチメニューまではお店側で済んでいて、「ギフトを贈る」ボタンがまだどこにもつながっていない状態から始まります。
