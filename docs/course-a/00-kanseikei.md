# 第0章 完成形を触ってみる

> この章でわかること：お客さんがギフトを贈る **2つの入口**（共通掲載・オリジナル）と、ギフトの一生（贈る → 受け取る → お礼）

教材アプリには、最初から見本のお店が入っています。

| お店 | 掲載方法 | お客さんの入口 |
|---|---|---|
| 見本バー | 共通掲載 | 運営の公式LINE「おくりギフト(dev)」→「お店をさがす」 |
| 見本カフェ | オリジナル | 見本カフェの公式LINE → リッチメニュー「ギフトを贈る」 |

どちらのお店も、オーナーは「あなた」（疑似スマホのLINEユーザー）になっています。まずはお客さんとして贈り、次にオーナーとして受け取ってみましょう。

## やること

### 入口①：共通掲載（運営の公式LINEから）

1. [疑似スマホ](http://localhost:3000/mock/phone) の友だち一覧から **おくりギフト(dev)** を開く
2. リッチメニューの **お店をさがす** → **見本バー** を選ぶ
3. ギフト（例：スタッフ乾杯用）を選び、メッセージを書く（例：みんなで乾杯してね！）
4. はじめてなので、支払いは **クレジットカード** で **カードを登録** する

   | 項目 | 入れる値 |
   |---|---|
   | カード番号 | `4242 4242 4242 4242` |
   | 有効期限 | `12/40`（今日より先ならなんでもOK） |
   | CVC | `123` |

5. 「ありがとうございました」の画面 → **✕ 閉じる** → おくりギフト(dev) から「ギフトを贈りました」が届いている

### 入口②：オリジナル（お店の公式LINEから）

6. ホームに戻り **見本カフェ** を開く → リッチメニュー **ギフトを贈る**
7. 支払いに **「登録済みのカード **** 4242」** が出ている。カード番号を入れずに贈れる
8. 今度は **見本カフェから** 「ギフトを贈りました」が届く

### オーナーとして受け取って、お礼を送る

9. おくりギフト(dev) のトークに「【見本カフェ】ギフトが届きました」が届いている
10. リッチメニューの **店舗管理** → 見本カフェの **ギフト一覧** → **受け取る**（ここで決済が確定）
11. **お礼を送る**：メッセージを書いて送信（動画があれば添付。なくてもOK）
12. お客さんに戻って、おくりギフト(dev) の **お礼一覧** を見る（見本バーには、初期データのお礼動画もあります）

| 自社サーバー | LINEにお願い POST /v2/bot/message/push … **運営（共通チャネル）のトークン**で |
| 自社サーバー | 注文 #○: リクエスト中 → 受取済み（仮押さえしていたカードの決済を確定） |
| 自社サーバー | 注文 #○: 受取済み → お礼済み |

## 考えてみよう

- ①と②で、お知らせを送ってきた公式LINEがちがいました。なぜでしょう？
- 「受け取る」を押すまで、お金は動いていませんでした。なぜ買った瞬間に確定しないのでしょう？

答えは第10章でわかります。

## この章のゴール

- 第1〜2章：**すべてのお店**に共通する作業（出店登録・商品登録・承認・手数料）
- 第3〜8章：**オリジナルを希望したお店**のための、公式LINEの構築（運営スタッフの主な仕事）
- 第9〜10章：代理店の紐付けと、動作確認

見本カフェと同じ状態を、**自分のお店で、ゼロから作る**のがコースAです。
