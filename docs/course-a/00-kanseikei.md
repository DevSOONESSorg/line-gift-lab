# 第0章 完成形を触ってみる

> この章でわかること：お客さんがギフトを贈る **2つの入口**（共通掲載・オリジナル）が、お客さんからどう見えるか

教材アプリには、最初から見本のお店が2つ入っています。

| お店 | 掲載方法 | お客さんの入口 |
|---|---|---|
| 見本フラワー | 共通掲載 | 運営の公式LINE「おくりギフト(dev)」→「ギフトを贈る」 |
| 見本カフェ | オリジナル | 見本カフェの公式LINE → リッチメニュー「ギフトを贈る」 |

まずはお客さんになって、両方の入口から贈ってみましょう。

## やること

### 入口①：共通掲載（運営の公式LINEから）

1. [疑似スマホ](http://localhost:3000/mock/phone) を開き、友だち一覧の **おくりギフト(dev)** を押す
2. 下のリッチメニューの **ギフトを贈る** を押す → 共通掲載のお店が並ぶ
3. **見本フラワー** を選び、商品と宛先（例：母）を入れる
4. はじめてなので **カードを登録** する

   | 項目 | 入れる値 |
   |---|---|
   | カード番号 | `4242 4242 4242 4242` |
   | 有効期限 | `12/40`（今日より先ならなんでもOK） |
   | CVC | `123`（3桁ならなんでもOK） |

5. 「ありがとうございました」が出たら **✕ 閉じる** → おくりギフト(dev) から「贈り物を受け付けました」が届いている

### 入口②：オリジナル（お店の公式LINEから）

6. ホームに戻り、友だち一覧の **見本カフェ** を押す
7. 下のリッチメニュー **ギフトを贈る** を押す → 見本カフェの贈る画面が開く
8. 支払いのところに **「登録済みのカード **** 4242」** が出ている。カード番号を入れずに購入できる
9. トークに戻ると、今度は **見本カフェから** 「贈り物を受け付けました」が届いている

## 裏側を見る

[裏側ビュー](http://localhost:3000/inside) を開いてみましょう（下から上へ、古い順）。

| だれ | 何をした |
|---|---|
| LINE社 | 「LIFF ○○ を開きます → エンドポイントURL …/liff/platform/shops」（入口①） |
| 自社サーバー | 共通掲載のお店一覧を表示した |
| 自社サーバー | カード **** 4242 を登録しました（次回からは入力不要） |
| 自社サーバー | 注文を受け付けた → 状態「リクエスト中」（共通掲載から） |
| 自社サーバー | LINEにお願い（push）… **運営のトークン** で、買った人にお知らせを送って |
| LINE社 | 「LIFF ○○ を開きます → エンドポイントURL …/liff/s/sample-cafe」（入口②） |
| 自社サーバー | 登録済みのカード **** 4242 で支払います |
| 自社サーバー | LINEにお願い（push）… **見本カフェのトークン** で、買った人にお知らせを送って |

## 考えてみよう

- ①と②で、「受け付けました」のお知らせを送ってきた公式LINEがちがいました。なぜでしょう？
- ②では、名前もカード番号も入れていないのに買えました。自社サーバーはどうやって「誰が買ったか」「どのカードか」を知ったのでしょう？

答えは第4章と第10章でわかります。

## この章のゴール

- 第1〜2章：**すべてのお店** に共通する作業（出店登録・商品登録・承認）
- 第3〜8章：**オリジナルを希望したお店** のための、公式LINEの構築（運営スタッフの主な仕事）
- 第9〜10章：代理店の紐付けと、動作確認

この流れで、見本カフェと同じ状態を **自分のお店で、ゼロから作る** のがコースAです。
