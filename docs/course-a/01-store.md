# 第1章 管理画面を見て、店舗を登録する

> 手順書 第1章に対応 ／ 使う画面：管理画面・スマホ
>
> この章でわかること：お店は「お店の人のLINE」から申し込まれる ／ slug とは何か ／ 承認の意味

## やること

### 管理画面を眺める

1. [管理画面](http://localhost:3000/admin) を開く
2. 左メニューに **店舗管理・注文管理・ユーザー管理・売上集計・代理店管理** が並んでいるのを確認する（これが操作盤）
3. 左下に **「LINE友だち登録」のQRコード** があります。これが店舗登録の入口です

### お店の人になって、出店登録する

4. QRの下の **「疑似スマホで読み取る」** を押す（本物では、スマホのLINEでQRを読み取ります）
5. 「おくりギフト(dev)」が表示されたら **追加** を押す
6. トークが開き、あいさつと案内が届きます。下のリッチメニューの **出店登録** を押す
7. 店名と最初のメニューを入れて **送信**

### 運営スタッフに戻って、承認する

8. 管理画面の [店舗管理](http://localhost:3000/admin/stores) を開くと、いま登録したお店が **「未承認」** で増えている
9. その行の **編集** を開く
10. 右側「管理設定」の **承認済み** にチェックを入れる
11. 左側「基本情報」の **スラッグ** を、自分で決めた slug に変える（例 `club-azure`）
12. 一番下の **更新** を押す。店舗管理に戻るとステータスが「承認済み」になっている

> 登録直後の slug は `store-3` のような仮の値です。本物の仕事でもここで slug を確定させます。**slug は一度決めたら変えません**（理由は下の「なぜ？」）。

## 裏側を見る

[裏側ビュー](http://localhost:3000/inside) で、次の流れを探してみましょう。

1. スマホ：「おくりギフト(dev)」を友だち追加しました
2. LINE社：Webhook送信 [follow] → 200 OK
3. 自社サーバー：Webhook受信 → 200 署名OK（運営LINE）: follow
4. 自社サーバー：LINEにお願い POST /v2/bot/message/reply → 200 （＝あいさつの返事）
5. LINE社：LIFF ○○ を開きます → エンドポイントURL …/liff/platform/register
6. 自社サーバー：出店登録を受け付けました（未承認）… **店舗管理者：登録した人のLINEユーザーID U…**

## なぜ？

**Q. なぜお店は、管理画面からではなくLINEから登録するの？**
お店の人の **LINEユーザーID** を手に入れるためです。LINEの中の出店登録画面から送信すると、「誰が送ったか」（ユーザーID）がいっしょに届きます。自社サーバーはそのIDを「このお店の店舗管理者」として保存します。あとで贈り物が届いたとき、この人のLINEにお知らせを送ったり、「受け取る」ボタンを押せる人を決めたりするのに使います。

→ [疑似スマホのホーム](http://localhost:3000/mock/phone) に出ている「あなたのユーザーID」と、[ユーザー管理](http://localhost:3000/admin/users) の「店舗管理者」のIDが同じことを確かめましょう。

**Q. slug（スラッグ）って何？**
URLの中に入る「お店の住所」です。このあと、次のURLに入ります。

| どこで使う | URL |
|---|---|
| 贈る画面（LIFFのエンドポイントURL） | `http://localhost:3000/liff/s/club-azure` |
| Webhook URL | `http://localhost:3000/api/webhook/line/store/club-azure` |

自社サーバーは、URLの slug を見て「どのお店の話か」を判断します。**あとで slug を変えると、LINE社に登録したURLと食いちがい、つながらなくなります。** だから「一度決めたら変えない」のです（第6章で実際に壊して確かめます）。

**Q. なぜ「承認」があるの？**
誰でもLINEから申し込めるので、運営が中身を確認してから公開するためです。未承認のお店は、贈る画面を開いても「準備中」になります。
