# 第3章 お店の公式LINEに、会社のアカウントを入れてもらう

> 手順書 第3章に対応 ／ 使う画面：Manager（＋ Dev Console を少し）
>
> この章でわかること：公式アカウントの「持ち主」と「作業する人」は別 ／ 招待URLのしくみ ／ プロバイダー＝会社の箱 ／ **有効化するときのプロバイダー選びが一番大事な理由**

ここからは、**オリジナルを希望したお店** のための構築作業です（共通掲載だけのお店には不要）。

実際の仕事では、**お店がもともと持っている公式LINEに、会社のアカウントを招待してもらい、会社側（運営スタッフ）で設定していく**流れです。課題のお店「クラブ アズール」も、公式LINE（とリッチメニュー）をもう持っています。ここではその流れを、1人2役で体験します。

## やること

### ① お店の公式LINEを確かめる（個人アカウント＝オーナー役）

1. [疑似Manager](http://localhost:3000/mock/manager) を開き、上の「ログイン中」が **あなたの個人アカウント（オーナー役）** になっていることを確認する
2. アカウントリストに **クラブ アズール** がある。お店がもともと持っている公式LINEで、オーナーが **管理者**（持ち主）です
3. 開いてみる。左メニューの **リッチメニュー** に、お店が使っているメニューがある（「ギフトを贈る」ボタンは、まだどこにもつながっていない）
4. 「ログイン中」を **会社の作業アカウント** に切り替えると、アカウントリストに **クラブ アズール が出てこない**。まだメンバーではないからです（確かめたら個人アカウントに戻す）

### ② 会社のアカウントに権限を渡す（個人アカウントで操作）

5. 左メニュー **権限管理** を開く（本番では、この操作をお店のオーナーにお願いして、URLを送ってもらいます）
6. 権限の種類で **運用担当者** を選び、**URLを発行** を押す
7. 発行されたURL（24時間有効・1回だけ）を **コピー** する

### 作業者を切り替える

8. 画面上部の「ログイン中」を **会社の作業アカウント（support役）** に切り替える
9. コピーしたURLを、ブラウザのアドレス欄に貼って開く → **参加する**
10. これ以降は **すべて会社の作業アカウントで** 操作します

### ③ Messaging API を有効化する（会社の作業アカウント）

11. 左メニュー **アカウント設定** で **ベーシックID（@xxx）** を控える（第5章で使う）
12. 左メニュー **Messaging API** を開く
13. 開発者情報を確認し、プロバイダーで **おくりギフト運営プロバイダー（株式会社サンプル）** を選び、**Messaging APIを利用する**（「あとから変更できません」の確認が出る）

これで、運営のプロバイダーの中に、このお店専用の **Messaging APIチャネル** ができました。会社の作業アカウントが作ったので、そのまま扱えます（次の章で使う）。

## 裏側を見る

- LINE社：招待URLを発行しました（24時間有効・1回だけ）
- LINE社：「会社の作業アカウント」が「○○」に運用担当者として参加しました
- LINE社：Messaging APIチャネルを作成しました … プロバイダー：おくりギフト運営 ／ **作成者（チャネルの権限を持つ人）：会社の作業アカウント**

## なぜ？

**Q. なぜ最初から会社のアカウントで作らないの？**
公式アカウントは **お店の財産** だからです（友だちもメッセージの履歴も、そのお店のもの）。持ち主（管理者）はお店のオーナーのまま、会社は「運用担当者」として作業だけ任される、という形にしておけば、契約が終わったときにお店が困りません。この体験では、あなたの個人アカウントがお店のオーナーの役です。

**Q. 招待URLが「24時間・1回だけ」なのはなぜ？**
URLを知っている人は誰でも参加できてしまうからです。期限と回数を絞って、URLがどこかに漏れても被害が出にくいようにしています。

**Q. プロバイダーって何？**
LINE Developers の中の **「会社の箱」** です。チャネル（Messaging API、LINEログイン）は必ずどれかの箱に入ります。大事なのは次の2つです。

1. **同じ人でも、箱がちがうとLINEユーザーIDがちがう。** 自社サーバーが「この人は第1章で出店登録したあの人だ」と分かるのは、同じ箱（運営のプロバイダー）の中だからです
2. **権限は2層。**「箱に入れるか（プロバイダーのメンバー）」と「そのチャネルを開けるか（チャネルの権限）」は別です。チャネルの権限は、**チャネルを作った人（有効化した人）にだけ**付きます

だから実際の手順書では「**会社のアカウントで・運営のプロバイダーを選んで**有効化する」が、太字の鉄則になっています。

## 壊してみよう（練習用の公式アカウントで）

有効化はやり直せないので、**練習用の公式アカウントをもう1つ作って** 試します。

1. 「ログイン中」を **あなたの個人アカウント** に切り替え、[作成](http://localhost:3000/mock/manager/create) で「練習用」という公式アカウントを作る
2. 権限管理で運用担当者のURLを発行し、会社の作業アカウントに切り替えて参加する
3. **ここで個人アカウントに戻して**、Messaging API を「新しいプロバイダーを作成：個人のプロバイダー」で有効化する（＝手順書でやってはいけない方）
4. 会社の作業アカウントに切り替えて、「練習用」の Messaging API 画面を見る →「**権限なし**」
5. [Dev Console](http://localhost:3000/mock/developers) を見ると、「個人のプロバイダー」そのものが見えない

**直し方**：個人アカウントに戻り、Dev Console でそのチャネルを開き、**権限設定（Roles）** タブで「会社の作業アカウント」を Admin として追加します。手順書の付録「権限のメモ」に書いてある対処と同じです。
