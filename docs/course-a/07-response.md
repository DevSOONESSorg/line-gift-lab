# 第7章 変える前に控えて、応答設定を整える（ケースA／B）

> 手順書 第7章に対応 ／ 使う画面：Manager・スマホ・管理画面
>
> この章でわかること：返事をするのは「LINE社の応答メッセージ」と「自社のbot」の2種類 ／ お店がキーワード応答を使っているか（ケースA／B）で設定が変わる ／ 設定を変える前に控える理由
>
> 構築ナビの手順5（控えて判定する）と手順13（応答設定）にあたります

## 本番で実際に起きた事故

キーワード応答を使って公式LINEを運用しているお店で、「手順書どおり」に **応答メッセージをオフ** にしました。すると、

- お店が使っていたキーワード応答（「お店の情報」「営業時間」など）が **全部止まった**
- お店のメニューのボタンを押しても、お店の案内のかわりに **ギフトの案内だけ** が返るようになった

お店から連絡が来て、はじめて気づきました。この章では、同じことを起こさないために

1. **変える前に控える**（手順5）
2. **ケースA／Bを判定する**（手順5）
3. **ケースに合わせて設定する**（手順13）
4. **最後に、お店のいつもの動きを確かめる**（手順17・第10章）

を練習します。この章も、**先に壊れた状態を体験** してから直します。

## 最初に：何も変える前に控える（手順5）

第3章で招待を受けて参加した **直後**、Messaging API を有効にする前にやります。

1. 会社の作業アカウントで [疑似Manager](http://localhost:3000/mock/manager) → お店 → 左メニュー「設定」の **応答設定** を開く
2. 「応答メッセージ」「あいさつメッセージ」のオン・オフを見る。**スイッチは押さない**（押した瞬間に保存されます。「保存」ボタンはありません）
3. 左メニュー「自動応答」の **応答メッセージ** を開く。**キーワード** の列に言葉が入っている行を数える（「**一律応答**」のバッジの行は数えない）
4. 左メニュー **リッチメニュー** を開き、ボタンごとの動き（リンク／テキスト）を見ておく。テキストのボタンの言葉が、応答メッセージのキーワードに並んでいないか
5. 構築ナビの手順5の欄に、見たとおりに入れて、ケースを選んで **控える**

### ケースの判定

| | ケースA（運用していない） | ケースB（運用中） |
|---|---|---|
| キーワード応答 | 0件（一律応答だけ） | **1件以上** |
| あいさつメッセージ | 作ったときの文面のまま | お店独自の文面のことが多い |
| リッチメニューのテキストボタン | ない（リンクだけ） | ある（押すとキーワードが送られ、お店の応答が返る） |

**キーワード応答が1件でもあれば、ケースB** です。

控えた内容が実際とちがうと、構築ナビに「控えた内容が、実際の『変更前の状態』と合っていません」と出て、先に進めません。控えた内容は、手順5の「完了」を開くといつでも見られます（右の「進み具合」のカードにも出ます）。

### 応答メッセージの一覧の見方

| 列・しるし | 意味 |
|---|---|
| キーワード | 送られた言葉と **完全に一致** したら返す。「お店の情報」は一致、「お店の情報は？」は一致しない。1行に1つ |
| 一律応答 | キーワードが空の行。どのキーワードにも当たらなかったメッセージ **すべて** に返す。公式アカウントを作った直後から1件入っている |
| 利用 | 行ごとのオン・オフ。応答設定の「応答メッセージ」がオフだと、ここがオンでも **どれも返らない** |

## やること（手順13）

第6章で Webhook を登録・検証し、「Webhookの利用」をオンにしたところから始めます。

### まず、いまの状態で話しかけてみる

1. [疑似スマホ](http://localhost:3000/mock/phone) の **左（お客さん）** で、構築中のお店のトークを開く（リッチメニューはまだ押せないので、左下のキーボードのアイコンから送る）
2. ケースBのお店（クラブ アズールなど）では、`営業時間` と送る → **返事が2通** 来る
   - 「営業時間 20:00〜翌1:00 …」（下に小さく **応答メッセージ**）… お店のキーワード応答
   - 「🎁 クラブ アズール へギフトを贈る `https://liff.line.me/…`」（下に小さく **bot**）… 自社の自動返信
3. `今日空いてる？` と送る →「メッセージありがとうございます！申し訳ありませんが…」（一律応答）と、bot のギフト案内の2通

### 壊してみる：ケースBのお店で、応答メッセージをオフにすると（あとで必ず戻す）

4. Manager の **応答設定** で「応答メッセージ」を **オフ**
5. もう一度 `営業時間` と送る → **お店の営業時間が返ってこない**。ギフトの案内だけが返る。これが本番の事故です
6. 裏側ビューに「キーワード『営業時間』の応答メッセージは登録されていますが、応答メッセージがOFFなので返しません」と出ている
7. 構築ナビの手順13にも「お店のキーワード応答が止まっています」と赤く出る
8. 応答メッセージを **オン** に戻す。応答メッセージの一覧で、「利用」が全部オンのままか確かめる

### ケースB の設定（手順5で「ケースB」と判定したお店）

9. Manager の **応答設定** を次のようにする（スイッチは押した瞬間に保存されるので、押す前に確かめる）

   | スイッチ | ケースB |
   |---|---|
   | チャット | オフ |
   | あいさつメッセージ | **オンのまま**（さわらない） |
   | Webhook | オン |
   | 応答メッセージ | **オンのまま**（さわらない） |

10. 管理画面 → お店の **編集** →「LINE 連携設定」の **テキスト受信時にギフト誘導を自動返信する** を **オフ** → **更新**
11. `営業時間` と送る → お店の応答（**応答メッセージ**）の1通だけ。`今日空いてる？` → 一律応答の1通だけ
    - お客さんは、リッチメニューの「贈る」ボタン（第8章）から贈ります

### ケースA の設定（手順5で「ケースA」と判定したお店）

12. Manager の **応答設定** を次のようにする

    | スイッチ | ケースA |
    |---|---|
    | チャット | オフ |
    | あいさつメッセージ | **オフ** |
    | Webhook | オン |
    | 応答メッセージ | **オフ** |

13. 管理画面の「テキスト受信時にギフト誘導を自動返信する」は **オンのまま**
14. `今日空いてる？` と送る → 返事は **bot の1通だけ**（「🎁 ○○ へギフトを贈る」＋リンク）

### 自社側の「ギフト誘導の自動返信」も試す（ケースAのお店で）

15. 管理画面 → お店の **編集** →「テキスト受信時にギフト誘導を自動返信する」をオフ → **更新**
16. もう一度送る → **何も返ってこない**（裏側ビューでは、Webhook は届いて署名もOKなのに、bot が返事をしていない）
17. 確かめたらオンに戻す

## 裏側を見る

ケースBのお店で、2 のときの裏側ビュー：

- スマホ：「営業時間」と送信しました
- LINE社：**応答メッセージ「営業時間」を自動で返しました**（キーワード「営業時間」に一致）
- LINE社：Webhook送信 [message] → 200
- 自社サーバー：Webhook受信 → 署名OK：message「営業時間」
- 自社サーバー：LINEにお願い POST /v2/bot/message/reply → 200

LINE社と自社サーバーが、**それぞれ勝手に返事をしている**ことがわかります。応答設定の変更も「応答設定を変更しました（チャット／あいさつ／Webhook／応答メッセージ）」として残ります。

## なぜ？

**Q. 応答メッセージと bot のちがいは？**

| | 応答メッセージ | bot（Webhook） |
|---|---|---|
| 返事をするのは | LINE社 | 自社サーバー |
| 中身 | Manager に書いた決まった文（キーワードごと・一律応答） | プログラム（[StoreBot.php](../../app/Services/Bots/StoreBot.php)）で考えた文 |
| 止め方 | Manager の応答設定の「応答メッセージ」をオフ（全部止まる） | 管理画面の「ギフト誘導を自動返信する」をオフ |
| 設定する場所 | Manager | 自社のプログラム・管理画面 |

公式アカウントを作った直後は、応答メッセージが **オン** で、一律応答が1件入っています。両方がオンだと、**両方が返事をして2通になります**。どちらを止めるかは、お店が応答メッセージを使っているかで決まります。

**Q. なぜケースBでは、応答メッセージをオフにしないの？**
応答メッセージのスイッチは **1つで全部** です。オフにすると、一律応答だけでなく、お店が作ったキーワード応答もまとめて止まります。お店の公式アカウントは **お店の財産**（第3章）です。お店が使っている応答を、運営が勝手に止めてはいけません。

**Q. では、ケースBで2通にならないようにするには？**
自社の側（管理画面の「ギフト誘導を自動返信する」）をオフにします。Webhook はオンのままなので、購入のお知らせなど、自社サーバーが必要なことは動きます。お客さんがギフトを贈る入口は、リッチメニューの「贈る」ボタンです。

**Q. ケースAで、あいさつメッセージをオフにするのはなぜ？**
友だち追加されたとき、自社の bot も follow イベントに返事をします。あいさつメッセージ（LINE社）もオンだと、2通になります。ケースAのお店は、あいさつを作ったときのまま使っていないので、オフにして bot にまかせます。ケースBのお店は独自のあいさつを使っているので、残します。

**Q. スイッチを押しただけで保存されるのは、なぜ注意？**
本物の Manager も、応答設定のスイッチは **押した瞬間に保存** されます。「保存しないで戻る」ができません。試しに押しただけで、お店の応答が止まります。だから、**押す前に控えておく**（手順5）のです。控えておけば、元に戻せます。

**Q. 「チャット」をオンにするとどうなる？**
「人が手で返事をする」モードになり、LINE社は Webhook を送らなくなります（この教材の仕様）。試してみましょう（裏側ビューに「メッセージを自社サーバーに送りません（応答モードが「チャット」になっている）」と出ます）。確かめたらオフに戻します。

**Q. Manager の「Webhook」と Dev Console の「Webhookの利用」はちがうもの？**
同じ1つのスイッチです。どちらで切り替えても、もう片方も変わります。

## 本物の仕事では

- 手順書の「応答メッセージをオフ」は、**運用していないアカウント（ケースA）向け** の標準手順です。お店がキーワード応答を使っているなら（ケースB）、そのまま従ってはいけません
- 変える前に、応答設定・応答メッセージの一覧・リッチメニューを **控えます**（画面キャプチャでもよい）
- 判定に迷ったら、ケースBとして扱い、上長とお店に確認します
