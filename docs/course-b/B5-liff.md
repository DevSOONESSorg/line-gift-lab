# B5 LIFF で「贈る」画面を開く

> コースA 第4章・第10章 の本物版です。本物のLINEの中で、あなたのPCの教材アプリのページが開き、あなたの名前が表示されます。

## 1. LINEログインチャネルと LIFF を作る

1. Developers Console → **B3 と同じ自分のプロバイダー** → **新規チャネル作成** → **LINEログイン**
   - 必ず **Messaging API チャネルと同じプロバイダー** に作ります（同じ箱の中でないと、LIFFで分かったユーザーIDにメッセージを送れない）
2. チャネル名・説明・アプリタイプ（**ウェブアプリ**）・メールアドレスなどを入れて作成
3. **LIFF** タブ → **追加**

   | 項目 | 入れる値 |
   |---|---|
   | サイズ | Full |
   | エンドポイントURL | 教材アプリの編集画面に出ている **公開用** のエンドポイントURL（`https://○○.trycloudflare.com/liff/s/{slug}`） |
   | Scope | `profile`・`openid` |
   | 友だち追加オプション | On（Normal）にすると、LIFF を開いたときに公式アカウントの友だち追加をすすめてくれる（リンクする公式アカウントの設定が必要な場合があります） |

4. できた **LIFF ID** を、教材アプリの編集画面の LIFF ID に入れて **更新**

### B0 で「方法B（メールアドレスのビジネスID）」を選んだ人

LINEログインチャネルが **「開発中」** のままだと、チャネルの管理者（あなたのビジネスID）以外は LIFF を開けません。スマホのLINEアカウントは別人扱いなので、チャネルの上部で **「公開」に切り替えて** ください。
（方法A の人は、自分がチャネルの管理者なので開発中のままで開けます）

## 2. 開いてみる

1. 教材アプリの **店舗詳細** に出る **店舗紐づけQRコード** を、スマホのLINEで読み取る
2. LINE の中で「贈る」画面が開き、「ようこそ ○○ さん」と **あなたのLINEの名前** が出る
   - 初回は「アクセスの許可」を聞かれます（profile を使ってよいか）
3. テストカード（`4242 4242 4242 4242`）で購入 → お店の公式LINEから「贈り物を受け付けました」が届く
4. 教材アプリの [注文管理](http://localhost:3000/admin/orders) に、あなたの本物のユーザーIDで注文が入っている

## 3. リッチメニューにつなぐ

- **Manager で作る場合**：B2 のメニューのどこかを、タイプ **リンク**・URL `https://liff.line.me/{LIFF_ID}` にする
- **API で作る場合**：`.env` に `LINE_LIFF_ID` を書かなくても、`--store` を付ければ店舗の LIFF ID が `{LIFF_ID}` に入ります

  ```bash
  docker compose exec app npm run richmenu -- --store yamada-real create richmenus/six.json richmenus/images/six.png
  ```

## しくみの確認

- 教材アプリの [src/views/liff/store.ejs](../../src/views/liff/store.ejs) の下の方にある `liff.init()` → `liff.getProfile()` が、名前とユーザーIDを取り出している部分です
- 疑似スマホのときは URL の `mock_uid` で「誰か」を渡していました。本物は LIFF SDK が LINE から受け取ります

> 教材アプリは「画面から送られてきたユーザーID」をそのまま信じています。本物のサービスでは、なりすましを防ぐため **IDトークン** をサーバーで検証します（B6 の発展課題）。

## 受け取りについて

「受け取る」は、コースAで運営の公式LINE（おくりギフト(dev)）から体験しました。コースBでは運営の公式LINEは作らないので、注文管理で「リクエスト中」になっていることの確認までで完了です。
