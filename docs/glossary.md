# 用語集

| 用語 | 意味 | 教材で出てくる場所 |
|---|---|---|
| 公式アカウント（LINE公式アカウント） | お店や会社が持つLINEのアカウント。友だち追加してもらい、メッセージを送る | Manager |
| ベーシックID | 公式アカウントのID。`@123abcde` の形。友だち追加のリンクに使う | 第3章・第5章 |
| Manager（LINE Official Account Manager） | 公式アカウントの管理画面。応答設定・リッチメニュー・権限管理など | 第3・7・8章 |
| 管理者／運用担当者 | 公式アカウントの権限。管理者はすべて、運用担当者は日々の運用（メンバー追加はできない） | 第3章 |
| LINE Developers Console | 開発者向けの管理画面。プロバイダー・チャネル・LIFF・Webhook を設定する | 第4〜6章 |
| プロバイダー | Developers の中の「会社の箱」。チャネルはどれかの箱に入る。箱がちがうと同じ人でもユーザーIDがちがう | 第3章 |
| チャネル | LINEの機能を使うための「窓口」。Messaging API チャネルと LINEログインチャネルがある | 第3〜5章 |
| Messaging API | プログラム（bot）から公式アカウントのメッセージを送受信するしくみ | 第3・5・6章 |
| チャネルID | チャネルの番号（10桁） | 第5章 |
| チャネルシークレット | LINE社と自社だけが知っている合言葉。Webhook の署名の確認に使う。ネットには流さない | 第5・6章 |
| チャネルアクセストークン | LINE社にお願いするときに見せる通行証。長期トークンは再発行すると古いものが使えなくなる | 第5章 |
| Webhook | 「何か起きたらこのURLに知らせて」という登録。LINE社 → 自社サーバー | 第6章 |
| イベント | Webhook で届く出来事。follow（友だち追加）、message（メッセージ）、postback（ボタン）、unfollow（ブロック）など | 第6・7章 |
| 署名（X-Line-Signature） | Webhook の本文をシークレットで計算した値。本物のLINE社からの通知かを確かめる | 第6章 |
| Verify | Webhook URL に中身のないテスト通知を送り、200 が返るか確かめるボタン | 第6章 |
| ステータスコード | サーバーの答えの番号。200＝OK、401＝本人確認失敗、404＝見つからない、500＝サーバーのエラー | 第6章 |
| reply（返信） | Webhook で届いた replyToken を使う返事。1回だけ・約1分以内。無料の通数に数えない | 第7・10章 |
| push（送信） | こちらから送るメッセージ。友だちでないと届かない。無料プランは月の通数に上限がある | 第10章 |
| 応答メッセージ | LINE社が自動で返す定型文（Manager で設定）。キーワードごとの応答と一律応答がある。応答設定のスイッチ1つで全部止まる。ケースAのお店ではオフ、ケースBのお店ではオンのまま | 第7章 |
| キーワード応答 | 送られた言葉がキーワードと **完全に一致** したときに返す応答メッセージ。お店が「お店の情報」「営業時間」などに使う | 第7章 |
| 一律応答 | キーワードが空の応答メッセージ。どのキーワードにも当たらないメッセージすべてに返す。公式アカウントを作った直後から1件ある | 第7章 |
| ケースA／ケースB | 構築するお店の公式LINEの状態。A＝運用していない（キーワード応答0件）、B＝運用中（キーワード応答が1件以上）。応答設定の中身が変わる | 第7章 |
| 変更前の状態を控える | 設定を変える前に、応答メッセージ・キーワード応答・あいさつ・リッチメニューを記録しておくこと（構築ナビの手順5）。判定と、元に戻すために使う | 第7章 |
| チャット（応答設定） | オンにすると、人が手で返事をするモードになり、Webhook（bot）が動かない。構築ではオフ | 第7章 |
| リッチメニュー | トーク画面の下に出るメニュー。1枚の画像＋押せる四角（当たり判定） | 第8章 |
| postback | 押しても画面にメッセージを出さず、データだけ bot に届けるボタン | コースB B4 |
| LIFF | LINE の中で開く、自社のWebページ。`https://liff.line.me/{LIFF_ID}` で開く | 第4・8・10章 |
| LIFF ID | LIFF アプリの番号。`チャネルID-8文字` の形。I と l、O と 0 のように見分けにくい文字が入るので、必ずコピーで貼る | 第4・5章 |
| LIFFアプリ詳細 | Dev Console の LIFF タブで LIFFアプリ名を押すと開く画面。1項目ずつ直せて、LIFF ID をコピーできる | 第4・5章 |
| 友だち追加オプション | LIFF を開いたとき、公式アカウントの友だち追加をすすめる設定。構築では On (normal) | 第4章 |
| リンクされたLINE公式アカウント | LINEログインチャネルの設定。友だち追加オプションで、どの公式アカウントをすすめるかを決める | 第4章 |
| 公開／開発中（チャネルの状態） | LINEログインチャネルの状態。開発中のままだと、お客さんが LIFF を開くと「400 Bad Request」になる | 第4章 |
| エンドポイントURL | LIFF ID を開いたときに、実際に表示される自社ページのURL | 第4章 |
| slug（スラッグ） | URL に入る「お店の住所」。一度決めたら変えない | 第1・4・6章 |
| ユーザーID | LINE の利用者の番号。`U` で始まる33文字。プロバイダーごとにちがう | 第1・10章 |
| オーナー（お店のオーナー） | 出店登録したLINEの人。口座登録・商品登録をし、贈り物の「受け取る」を押す | 第1・10章 |
| 共通掲載 | 運営の公式LINEの「お店をさがす」にお店を並べる掲載方法。お店の公式LINEはいらない。オフでもお店のURL・QRからは贈れる | 第0・2・10章 |
| オリジナル | お店自身の公式LINEのリッチメニューから贈れるようにする掲載方法。運営が公式LINEを構築する | 第3〜8章 |
| 運営の公式LINE | サービス全体の公式LINE（教材では「おくりギフト(dev)」）。お客さんの共通掲載の入口と、オーナーの出店登録・店舗管理の入口 | 第0・1・10章 |
| カード登録 | 初回の購入でカードを登録し、2回目からは入力不要にするしくみ。自社は下4桁などの目印だけを持つ | 第10章 |
| 月別手数料率 | その月だけ手数料率を変える設定。ない月はデフォルト手数料率 | 第2章 |
| 商品テンプレート | 運営が用意する「よくある商品」の見本。オーナーはここから選べる | 第1章 |
| お礼動画 | お店が受け取ったあと、お客さんに送る動画。見せるときは署名付きURL | 第10章 |
| 仮押さえ（与信・オーソリ）／確定 | カードの枠だけ確保しておく状態と、実際にお金を動かす状態。与信には期限がある | 第10章・C2 |
| 状態遷移 | 注文の状態（リクエスト中→受取済み→お礼済み…）の移り変わり。移ってよい先が決まっている | 第10章・C1 |
| 署名付きURL | 期限と署名が付いたURL。書きかえたり期限が過ぎたりすると開けない（お礼動画に使う） | 第10章・C3 |
| CSRF トークン | フォームに埋め込む合言葉（`_token`）。よそのサイトから勝手に送信されるのを防ぐ | C4 |
| フォールバック | 本来の道が使えないとき、代わりの道を使う設計（店舗チャネル未設定 → 共通チャネル） | 第10章・C6 |
| マイグレーション | テーブルの設計図。`php artisan migrate` で実行 | C0 |
| artisan | Laravel のコマンド（`php artisan route:list` など） | C0 |
| スケジューラー | 決まった時間に処理を動かす仕組み（期限切れの自動処理） | C2 |
| 代理店（1次・2次） | お店を紹介してくれる会社。報酬＝売上×報酬率。1次に支払い、2次は1次から受け取る | 第9章 |
| トンネル | インターネット → 自分のPC への一時的な入口（cloudflared） | コースB B3 |
