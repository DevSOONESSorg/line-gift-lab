# C7 本番を触るときの約束

実物の仕事では、**本番環境（お客さんが実際にお金を払っているシステム）** を触ることがあります。仕組みがわかっていても、本番での1回のミスは取り返しがつきません。

## 環境を分ける

| 環境 | 目的 | 管理画面の表示 |
|---|---|---|
| dev（開発） | 自由に試す | DEV |
| stg（検証） | 本番と同じ形で、公開前の確認 | STG |
| prod（本番） | お客さんが使う | **PROD** |

教材の右下にも DEV と出ています（`.env` の `APP_STAGE`）。**画面を開いたら、まず右下を見る** のを習慣にしましょう。

## 本番で守ること

1. **見るだけのときは、見るだけ**：一覧・詳細を開く。フォームは送信しない。「保存」「更新」「取消」「削除」は押さない
2. **押す前に声に出す**：「PROD の管理画面で、○○店の、△△を、□□に変えます」
3. **確認ダイアログは読む**：反射で OK を押さない
4. **シークレット・トークン・個人情報は、コピーしない・貼らない・写さない**
5. **わからなくなったら止まって、人に聞く**

## 見るだけで調べる方法

画面の作りを調べたいとき、本番のデータは変えずに、ブラウザの **開発者ツール** で読むことができます。

- 「要素」タブ：フォームの `name`（例 `line_messaging_channel_secret`）、`action`（送信先のURL）
- 「ネットワーク」タブ：画面を開いたときにどんな通信をしているか

> この教材は、実物の管理画面を **見るだけ** で調べて作りました（項目名・画面の構成・URLの形・状態の種類）。そのときに気づいた改善点（確認ダイアログ、動画URLの署名）も、教材には入れてあります。

## 課題

| レベル | 内容 |
|---|---|
| C7-1 | `.env` の `APP_STAGE=prod` にして再起動し、管理画面の見え方を確認する。本番のときだけ、画面の上に赤い帯「本番環境です」を出す改修をする |
| C7-2 | 「本番では承認の取消・店舗の削除ができるのは、特定の管理者だけ」にする設計を考える（どのテーブルに何を足し、どこでチェックするか）。文章と図でOK |
